# この作品を、自分で説明できる作品にする

何も見ずに全文を書ける必要はありません。資料を見ながらでも「入力→判断→保存→表示」を追い、変更後の結果を確認できることを最初の目標にします。期間は目安です。

## 1日目：動かして流れを追う

- START_HEREの操作を実施する。
- Ticket.javaの項目を日本語で説明する。
- createからsaveAllまでコードを追う。
- 画面の見出しを1つ変える。

## 2〜3日目：小さく変更する

- 分類に「ソフトウェア」を追加する。
- 件名の上限を80文字から100文字に変更する。
- 「件名が長すぎる」テストも新しい境界に変更する。
- 本文だけに含まれるキーワードでも検索できるテストを追加する。

注意：上限はServiceだけでなく、HtmlViewsのmaxlengthと案内、README、テストも合わせる。複数箇所の整合性を保つ練習です。

## 4〜7日目：自分の機能を1つ実装する

「分類で絞り込む」をおすすめの練習課題とする。答えのコードはあえて完成させていません。

1. 一覧に分類の選択欄を追加する。
2. Controllerで選んだ分類を受け取る。
3. Serviceで分類が一致するかを判断する。
4. キーワード・状況・分類の3条件を同時に使えるようにする。
5. 検索後も選んだ条件を画面に表示する。
6. 条件なし／一致／不一致／複数条件のテストを追加する。
7. MY_CHANGESに変更した理由と失敗した点を書く。
